# AI 聊天室国际化(zh/en)设计文档

日期:2026-09-08
状态:已确认(分节逐节确认完毕)

## 1. 目标与范围

为 AI 聊天室 v2 添加中英双语支持,覆盖三层:

1. **前端 UI**(web/src,约 400 条文案):组件模板、script、useDialog、api 错误、状态映射、avatar 色板、导出文档。
2. **后端系统消息**(server/src A 类,约 90 条):orchestrator/room/direct/admin/subscribe 的 WS 广播 system 消息、REST 错误、fromName 显示名、ws hello。
3. **AI prompt**(server/src B 类,约 230 处):buildPrompt/buildDeltaPrompt/侦察/摘要/接棒教学/心跳两阶段/私聊纪要等,语言跟随 UI 语言。

**明确不做**(YAGNI):多语言框架预留、存量数据迁移、历史消息重译、RTL、前端测试基建、codex/gemini 适配器改动。

## 2. 已确认的决策

| 决策点 | 选择 |
|---|---|
| 覆盖范围 | 全量(前端 + 后端系统消息 + AI prompt) |
| prompt 语言 | 跟随 UI 语言(同一设置) |
| 存量数据 | 不迁移,历史消息/资产保持原样 |
| 语言切换 | 运行时切换 + 持久化(后端 settings 权威 + localStorage 首屏缓存) |
| 导出文档 | 标题/字段名随 UI 语言 |
| 协议标签 | **双语化**:英文模式教英文标签,解析器中英并集匹配 |
| 语义兜底推断 | 双语匹配(不论当前语言,中英语料并集) |

## 3. 总体架构

### 3.1 语言真源与流转

后端为语言权威,经构造注入流经 core;前端管自己的 UI 词典。

```
用户点切换(zh↔en)
  → 前端: localStorage 记住 + vue-i18n locale 立即切换 + <html lang> 更新
  → PUT /api/settings/language { lang: 'en' }
      → server: store/settings.json 原子写(复用 rooms.json 串行写模式)
      → 内存 LangProvider 值更新

之后一切后端产物按新语言发射:
  orchestrator 系统消息 → t(lang, 'baton.pass', {from, to}) → 落库/广播已是英文
  buildPrompt(lang) → 英文 prompt 段落 + 教英文标签
  AI 用英文标签回复 → 解析器双语匹配 → 接棒链继续

刷新页面 → GET /api/settings → 校正前端 locale(后端权威,localStorage 只是首屏快速值)
```

- 默认 `zh`:settings.json 不存在时行为与现状完全一致(向后兼容)。
- 运行时切换不中断进行中的编排:单条消息语言在发射瞬间定死;流式中的 agent 收到的 prompt 已确定。
- 切语言后,历史系统消息保持切换前语言(与「存量不迁移」哲学一致)。

### 3.2 core/lang.ts(新增叶子,零依赖)

```ts
export type Lang = 'zh' | 'en';
export interface LangProvider { get(): Lang }
export function t(lang: Lang, key: string, params?: Record<string, string|number>): string
```

`LangProvider` 按项目 DI 模式构造注入:server 装配时创建(读 settings.json),传入 `new ChatRoom(...)` → ChatRoom 传给 Orchestrator/DirectChat/admin。**core 保持零 store import(契约防线不破)**。

### 3.3 ChatMessage 契约零改动

系统消息正文、fromName('系统'/'用户'/'🔍 侦察员')全部在**发射时刻**按当前语言烘焙成文本落库/广播。JSONL 历史、导出逻辑、既有测试断言格式全不受影响。这是本方案(方案 A)相对"消息协议 key 化"(方案 B)的核心优势:后者要改 ChatMessage 契约、新旧消息混合渲染、测试/导出全适配,对单用户本地应用收益小成本高。

### 3.4 REST/WS

- 新增 `GET /api/settings`、`PUT /api/settings/language`(校验 `zh|en` 枚举)。
- routes 层错误消息直接 `t(lang, ...)`(routes 在 server 层,可直引 settings)。
- ws.ts hello 消息同理双语。

## 4. 协议标签双语化(地基,风险最高)

### 4.1 单一真源:core/modes/protocolKeywords.ts

普查发现协议标签正则至少 15 处内联重复、无单一真源(orchestrator.ts:1012 重复 BATON_LINE、audience.ts 4 处内联握手正则、trace.ts `includes('<跳过>')`、@点名正则 8 处内联)。直接双语化会 ×2 放大此债,故先收口再双语。

```ts
/** 接棒: 双语标签并集匹配,发射(prompt 教学)时按语言选一侧 */
export const BATON_TAGS = ['<接棒>', '【接棒】', '<pass>', '<PASS>'] as const;
export const BATON_END_WORDS = /结束|收敛|无需|到此|end|conclude|wrap/;
// 私聊标签、握手三件套、沉默/跳过词表同理收口
```

- **匹配 = 并集**:不论当前语言,中英标签都能解析(历史中文消息、英文模式 AI 输出、AI 不听话写中文标签,全兼容)。
- **发射 = 按语言选一侧**:中文模式教 `<接棒>`,英文模式教 `<pass>`;标签从常量表取,是数据不是文案。
- 15 处内联正则全部改为引用此真源。
- @点名正则的截断符取中英并集(不丢现有行为)。

### 4.2 标签命名

| 中文 | 英文 |
|---|---|
| `<接棒>` / `【接棒】`(旧) | `<pass>`(旧式仅中文保留) |
| 接棒结束词(结束/收敛/无需/到此) | end / conclude / wrap up |
| `<私聊>` | `<dm>` |
| `<同意>` / `<拒绝>` / `<想法>` | `<agree>` / `<decline>` / `<idea>` |
| `<跳过>` / `<沉默>` | `<skip>` / `<silent>` |

英文词实现时可微调(`<pass>` 是否误触发待验证,备选 `<baton>`);收口后换词只改一处。

### 4.3 语义兜底推断

`audience.ts` 的 `inferHandshakeFromText`(中文语料正则)与 `subscribe/prompt.ts` 的 `isSilentDecision`(10 个字面量):词表搬入 protocolKeywords.ts,中英并集,不论当前语言并行匹配。兜底路径并集变宽的风险可接受,不破坏主路径。

### 4.4 前端侧

前端不能 import server 包(两个 workspace),建 `web/src/utils/protocol.ts` 独立定义同一套双语标签并集(与后端 protocolKeywords.ts 注释互指同步),MessageBubble 与 exportMarkdown 共用——顺带消除普查发现的"接棒意图解析前端双份实现"。

## 5. 后端词典

### 5.1 core/i18n/ 目录

```
core/i18n/
├── (lang.ts)     Lang / t / LangProvider
├── messages.ts   A 类文案词典(zh/en,~90 条)
└── prompts.ts    B 类 prompt 段落词典(zh/en,~230 处,按段落模板组织)
```

**messages.ts 结构**(key 按域分组,插值用函数参数,纯 TS 零依赖):

```ts
export const MESSAGES = {
  zh: {
    'room.memberJoined': ({ names, count }) => `${names} 加入了房间,当前 ${count} 位成员`,
    'baton.pass':        ({ from, to }) => `🎯 ${from} 把接棒交给 ${to}`,
    'sys.stoppedThinking': () => '(已停止思考)',
    ...
  },
  en: { ... } // Record<keyof typeof zh, ...> 强制同 key 集,漏译编译错
}
```

覆盖:orchestrator ~25 条、room/direct ~15 条、subscribe silent 通知 ~5 条、admin 熔断 ~3 条、routes REST 错误 ~30 条、ws hello、fromName 三件套、trace trigger/memberName。

### 5.2 prompts.ts:按段落模板双语化

不逐句抽词典,每个 prompt 组装函数(buildPrompt/buildDeltaPrompt/buildScoutPrompt/心跳两阶段/私聊纪要/公聊摘要)签名加 lang,内部引用词典段。**组装逻辑(顺序/拼接/分支)不动,中文句子换成词典引用**。

- render.ts 转录标签(`【私聊密信】`等)进词典;发射按语言走,历史中英标签混存是预期行为,解析侧并集已覆盖。
- admin 摘要 prompt 的固定 Markdown 标题双语化;摘要快照旧中新款混存,前端按文本展示无需适配。

## 6. 前端方案

### 6.1 vue-i18n@9

~400 条规模值得成熟库(插值/复数/reactive locale)。仅两语言,词典打包进去不懒加载。

```
web/src/i18n/
├── index.ts   createI18n + 全局 t 导出
├── zh.ts / en.ts   typeof zh 锁 en shape
```

### 6.2 locale 流转

```
初始 locale = GET /api/settings.language(后端权威)
  ← 失败 fallback: localStorage ?? navigator.language 判定 ?? 'zh'

setLang(lang):
  i18n.global.locale = lang
  localStorage.setItem('ai-chatroom:lang', lang)
  document.documentElement.lang = 'zh-CN' | 'en'
  document.title = t('app.title')
  PUT /api/settings/language
```

### 6.3 抽取要点

- key 按组件域分组,插值用 `{name}` 语法。
- 状态映射字典(idle/thinking/streaming/error、模式名)→ key 映射表 + t()。
- 三目内嵌中文拆两个 key。
- useDialog 调用点直接传 t() 渲染结果,不改其接口。
- api.ts 错误直接 import 全局 t(运行时取值,locale reactive)。
- avatar.ts 色板 label、markdown.ts「复制/已复制」按钮注入走词典(旧渲染 HTML 缓存不重译,可接受)。
- exportMarkdown.ts(~50 条)随 UI 语言。
- index.html `<title>` 初始化后动态设;`lang` 属性动态改。
- 切换入口:Sidebar 内 zh/EN 切换控件,实现时按现有布局风格定,不加新弹窗。
- 开发期启用 missingWarn 防漏译。

## 7. 测试策略

**既有 1255 处中文断言 = 行为锁**,zh 默认路径全部保留且必须通过。唯一允许改动:prompt 文案级断言因抽取微调措辞而同步;协议标签断言因双语并集**增补**而非替换。

新增测试(server 侧,core 注入 LangProvider fake):

| 文件 | 覆盖 |
|---|---|
| protocol-keywords.test.ts | 双语标签并集解析(`<接棒>@张三` ≡ `<pass>@Bob`;`<pass>end` 结束;`<dm>`/`<agree>` 握手;@截断符并集;isSilentDecision/inferHandshake 双语) |

### 手工验收清单

1. zh 模式全流程与现状无差异(默认路径零回归)
2. 切 en → 界面全英、系统消息(加人/离人/接棒传递/停止思考)为英文
3. en 模式发起讨论 → AI 收英文 prompt、写英文标签、接棒链正常传递
4. en 模式私聊握手(agree/decline/idea/dm)解析正常
5. 切回 zh → 新系统消息回中文,中英混合历史正常显示
6. 导出 Markdown 为英文标题/字段
7. 刷新页面语言保持(后端权威 + localStorage)
8. 旧数据:既有中文房间/角色/历史消息在 en 模式下正常显示与交互

## 9. 风险清单

- **协议标签误触发**:英文标签词形(如 `<pass>`)可能撞正文;实现时验证,必要时换 `<baton>` 等更特异词形;收口后换词只改一处。
- **A/B 混杂文件**:orchestrator.ts 同文件 sysNotice(A)与 trigger(B)交错,改造时逐处判定归类,勿混。
- **前端双份接棒解析**:MessageBubble 与 exportMarkdown 重复实现,借切片 7 收口到 web/src/utils/protocol.ts。
- **prompt 文案级测试断言**:baton/subscribe 测试直接断言 prompt 片段,抽取时措辞尽量原样搬入词典,减少断言 churn。
- **切语言时正在流式的 agent**:prompt 已定,不受影响;其后续消息按新语言(预期行为)。
