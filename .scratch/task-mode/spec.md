# Spec: 任务模式(任务房 + 权限真实化 + 斜杠命令)

Status: ready-for-agent
Created: 2026-09-24
ADRs: docs/adr/0001-task-is-room-kind.md, docs/adr/0002-permission-tiers-real.md
Glossary: CONTEXT.md(房间/任务房/工具权限档位/斜杠命令/任务状态/超时保护)

## Problem Statement

我(单用户)想把这个多 agent 聊天室当作 agent 工作台用:给每个 agent 派一个编程任务,每个任务绑定一个不同的本地项目目录,多个任务并行跑。但现状有四个障碍:

1. **房间只会"讨论"**:prompt 教学写死了"围绕项目发表观点、300 字内发言、接棒续聊"——agent 被教成辩论者,不会真正动手改代码、汇报结果。派出去的任务 agent 只会夸夸其谈。
2. **权限档位名不副实**:实测发现 readonly 房的 agent 能写文件、能跑任意命令(全局 bypassPermissions 拆闸 + `--allowedTools` 是预批准而非限制);"readwrite"实际等于"full"。我对"派出去的 agent 到底能干什么"的预期是错的。
3. **没有任务视角**:任务和闲聊房混在同一个房间列表,开 5 个任务后无法一眼扫出各自状态;编程任务一跑十几分钟,卡死和正常干活分不清,也没有超时保护。
4. **没有命令入口**:直接用 claude CLI 有 /compact、skills 等能力;聊天室里这些全都够不着——上下文膨胀只能等自动压缩,skill 无法从输入框触发。

## Solution

在现有房间引擎**零语义分叉**的前提下:

- 新增**任务房**(`kind: 'task'` 的房间):必填项目目录、任务化 prompt 教学(真正干活→汇报→遇阻先问)、默认 full 权限 + stateful 会话续跑;侧边栏新增**任务 tab** 一等公民呈现(三态灯列表)。
- **权限三档真实化**:claude 加 `--disallowedTools` 硬闸(readonly 真只读、readwrite 真无命令无网络、full 明示全开),extraArgs 加白名单堵注入面,prompt 权限文案与实际行为对齐。
- **斜杠命令层**:输入框敲 `/` 弹命令候选(内置 /compact /model /skills + 动态扫描的 skill 命令),skill 经自然语言触发。
- **超时保护**:单次发言可配上限,超时走 cancelled 轨道(不清 session、不自动重试),系统消息提示可重发续跑。

## User Stories

### 任务房与任务派发

1. 作为用户,我想创建一个任务房(选项目目录 + 选角色 + 一句话任务),这样 agent 就在一个独立项目里为我干活
2. 作为用户,我想让任务房绑定必填的项目目录,这样 agent 的相对路径操作天然落在项目内、且自动加载该项目的 CLAUDE.md/skills
3. 作为用户,我想在建任务时用预设的"工程师"角色模板一键填充人设,这样不必每次手写任务行为契约
4. 作为用户,我想把任意已有角色(含自定义人设)拉进任务房,这样角色个性在任务里也保留(persona 照常注入)
5. 作为用户,我想派任务后 agent 直接动手用工具读代码、改代码,而不是只输出一堆方案描述
6. 作为用户,我想让 agent 干完活汇报:做了什么、改了哪些文件、如何验证,这样我不用自己去翻 diff
7. 作为用户,我想让 agent 遇到需求不清或阻塞时先问我,这样它不会基于误解狂奔半小时
8. 作为用户,我想任务汇报不受发言长度约束(不用聊天房的 300 字限制),这样汇报完整不被截断
9. 作为用户,我想给任务房加第二个成员(如 A 写码 + B review),这样多 agent 可以协作同一个项目
10. 作为用户,我想任务房多成员协作直接用既有的手动 @ 点名驱动(成员干完即停;我停止后再 @ 下一位),这样协作节奏由既有机制承载,零新设计

### 会话与上下文

11. 作为用户,我想任务房默认用 stateful 会话(增量 prompt + session resume),这样长任务的上下文连贯且省 token,和直接用 CLI 同构
12. 作为用户,我想任务房的 CLI session 跨重启保留(sessionIds 持久化),这样服务重启后发一句"继续"就能续跑,前功不弃
13. 作为用户,我想消息数超阈值时自动 compact 当前 agent 的上下文,这样长任务不会撑爆 session
14. 作为用户,我想在输入框手动触发 /compact,这样不等自动阈值也能主动压缩
15. 作为用户,我想手动 /model <name> 切换某个任务 agent 的模型,这样简单活可以切便宜档

### 权限真实化

16. 作为用户,我想 readonly 档真正只读(disallow 写文件/跑命令/联网),这样"只分析不改"类任务名副其实
17. 作为用户,我想 readwrite 档真正"仅文件读写"(disallow 命令/联网/子代理),这样派出去的 agent 不会偷偷跑 npm 脚本或外发数据
18. 作为用户,我想 full 档明示完全权限(含命令与网络),这样选它时我清楚知道代价
19. 作为用户,我想任务房默认 full(跑测试是刚需),这样正常编程任务开箱即用
20. 作为用户,我想 prompt 里告诉 agent 的权限说明与实际行为一致,这样 agent 不会自以为受限或自以为全开
21. 作为用户,我想角色卡/建房/导入来的 extraArgs 只放行白名单参数(--model/--thinking-budget),这样别人给的角色卡夹带不了 --dangerously-bypass 私货
22. 作为用户,我想知道三档管的是工具种类不是路径范围(readonly 也能读项目外文件),这是已知接受边界——prompt 教学里写"工作仅限此项目目录"作为软约束

### 任务 tab 与状态可见性

23. 作为用户,我想侧边栏有一个独立的任务 tab(与房间/角色并列),这样任务不和闲聊房混排
24. 作为用户,我想任务列表每行显示状态灯 + 任务名 + 绑定项目 + 最后动态时间,这样扫一眼知道每个任务在干活/空闲/出错
25. 作为用户,我想任务按最近活跃排序,这样最热的任务总在最上面
26. 作为用户,我想任务状态只有三态(空闲/进行中/出错)且实时从成员状态映射,这样没有会撒谎的"自动完成"状态,验收由我看消息流自己判断
27. 作为用户,我想点任务行进入的就是现有房间视图(消息流/trace/输入框),这样不用学新界面
28. 作为用户,我想气泡上看到"最后事件时间"且长时间无输出有提示,这样能区分"在干活"和"卡死"

### 超时保护

29. 作为用户,我想单次发言有可配的超时上限(全局配置项 + 房间可调,**默认无超时**,需我手动启用),这样默认行为不变,失控烧钱的 agent 由我按需设卡
30. 作为用户,我想超时后看到系统消息"超时已停止,可重发继续",这样我知道发生了什么、怎么办
31. 作为用户,我想超时不清理 CLI session 也不自动重试,这样重发消息即 resume 续跑(而非从零再来或自己又跑一轮)

### 斜杠命令与 skill

32. 作为用户,我想输入框敲 `/` 弹出命令候选层(和 @ 提及同款交互),这样命令可发现、不用背
33. 作为用户,我想候选列表包含我装的 skills(用户级 + 项目级动态扫描),这样输入框变成 skill 启动器——技能盘点也由此完成
34. 作为用户,我想选中 skill 命令后补两句话回车,agent 就按该 skill 干活(自然语言触发),这样得到与交互式 CLI /skill 等价的体验

### 导入导出与兼容

35. 作为用户,我想把任务房导出/导入往返(kind 字段随配置走),这样任务配置可备份迁移
36. 作为用户,我想导入时若 task 房的项目路径本机不存在则降级为聊天房并落系统消息警示,这样不产生"无项目的僵尸任务房"(agent 落到共享临时目录干活),也保住"导入永不失败"
37. 作为用户,我想存量聊天房读时默认 kind:'chat',这样升级后一切照旧
38. 作为用户,我想任务房的设置面板只显示相关设置(隐藏接棒预算/订阅配置等),这样不被无关项干扰

### i18n

39. 作为用户(zh/en),我想任务 prompt 段、系统消息、任务 tab 文案都有双语,这样语言切换行为一致

## Implementation Decisions

### 任务房(kind)

- RoomConfig 加可选字段 `kind: 'chat' | 'task'`,缺省 'chat'(存量零迁移;与 mode/contextMode 字段演进先例同构)。
- 建房路由校验:task 房 projectPath 必填(不存在则 400)、mode 恒锁 'baton';聊天房照旧。
- 任务房默认值束(表单/路由层实现,引擎不感知):toolPermission 默认 full、contextMode 默认 stateful、成员 1 起步可加、无 Scout 预检(kind=task 跳过 ensureScout)。
- **复用边界以编排语义为界,不以文件为界**(ADR-0001):编排循环/世代计数器/cancel 三态/resume 自愈/compact 防踩踏零改动。严禁 fork 编排器/store 做"任务版"。kind 在领域层的全部足迹 = 类型字段 + prompt 教学段分支 + scout 跳过。
- 多成员任务房 = 手动 @ 点名驱动协作(复用既有 @ 待命/停止语义,成员干完即停);无自动链,零新机制。
- 导入降级:task 房 projectPath 本机不存在 → 导入为 chat 房 + 系统消息警示(不拒绝导入)。
- 导出含 kind 字段,往返保真。

### 任务 prompt 契约

- kind='task' 时 buildPrompt/buildDeltaPrompt 换任务段族(进 B 类 prompt 词典,zh/en 双写):
  - 工作区段:项目根路径 + 真实权限说明(与档位实际行为对齐)+ "工作仅限此项目目录"范围约定 + 自主探索引导。**不注入目录树**(agent 用工具自查实时结构)。
  - 行为契约:实际用工具修改/创建代码勿只描述;汇报做了什么/改了哪些文件/如何验证;遇阻先问;不限长度。
  - 砍掉:参与者列表(单成员)、接棒教学、发言长度约束、"直接以角色身份发言"的讨论式指令。
- persona 照常注入(表单提供工程师模板便利填充)。

### 权限三档真实化(ADR-0002)

- claude 适配器加 `--disallowedTools` 硬闸(与 --allowedTools 并存;实测有效且不受全局 bypassPermissions 影响)。disallow 契约:
  - readonly: `Write Edit NotebookEdit Bash Task Agent KillShell WebFetch WebSearch`
  - readwrite: `Bash Task Agent KillShell WebFetch WebSearch`
  - full: 不限制
- WebFetch/WebSearch 仅 full 可用(Read 不限路径前提下,网络是数据外发唯一出口)。
- qwen(--approval-mode plan/auto-edit/yolo,三档实测)/gemini(同形 flag,文档语义)/codex(--sandbox)维持既有翻译与测试锁。
- extraArgs 白名单 = **单一校验函数**收口全部入口(角色创建/角色卡导入/建房成员/房间导入成员/角色导入):仅放行 `--model` 与 `--thinking-budget`(带格式校验),其余拒绝并警告。
- promptTexts 权限说明三档文案按真实语义改写(zh/en;zh 侧改动须同步既有测试断言)。

### 超时保护

- agents.yaml 全局配置项 + 房间可调,**默认无超时(无限)**——用户手动启用才生效,保守默认不替用户做主。
- **实现为 cancelled 语义,严禁走 error 轨道**(error 自愈会清 sessionIds + 自动重试,与超时语义相反——orchestrator invokeWithRetry 已验证行为)。
- harness 层加可配置计时上限,超时触发 cancel(killTree);SpeakOutcome 加 `timedOut` 标记区分"用户停"与"超时停";编排器按标记落占位消息"(超时已停止,可重发继续)"。cancelled 轨道既有保证(不清 session/不重试/保留半截正文)全部继承。
- 前端活性指示:气泡"最后事件时间" + 长时无输出提示(纯前端,读现有事件流)。

### 斜杠命令

- 输入框 `/` 触发命令候选层,与 @ 提及同套弹层与解析管线(mentions 单一真源加 `/` 分支)。
- 内置命令(硬编码):/compact(压缩当前 agent session,本地动作,复用 compact 基建)、/model <name>(切模型,下次发言生效,需新增成员变更路由)。不做 /skills 询问(skill 候选列表已覆盖盘点需求)。
- skill 命令(动态):server 端点扫描 `~/.claude/skills/` + 项目 `.claude/skills/` 生成候选;选中后组装"使用 X skill 执行:<补充说明>"的 prompt 发给 agent(自然语言触发,实测可用;CLI 的 /skills /mcp 在 headless 不存在)。
- 未知 `/xxx` 不做拦截——敲了就当普通文本发出(agent 自然回应或无视),前端不加报错逻辑。
- 边界:skill 是否真用是模型决策(实测即从,非硬保证)。

### UI(前端)

- 侧栏新增任务 tab(与房间/角色并列);任务行 = 三态灯(空闲/进行中/出错,直通映射成员状态)+ 任务名 + 项目名(路径尾段)+ 最后动态时间;活跃倒序;点击进入复用现有 RoomView。
- 任务专属简表单:任务名 + 项目路径(必填)+ 角色(下拉含工程师模板)+ 权限档(默认 full);不出现聊天概念字段。
- 设置面板按 kind 条件渲染(task 隐藏 chainBudget/subscribeConfig/mode 等);RoomSettings PATCH 对 task 房过滤无关字段。

### i18n

- 任务段族进 promptTexts(zh/en 双写,新键不受既有字节锁约束但键集须齐);超时占位消息走 messages.ts A 类;任务 tab/表单/命令层文案进前端 zh/en 词典。

## Testing Decisions

**好测试只测接缝处的外部行为**(输入→可观察输出),不测内部实现细节;状态断言经公开 API/消息流,不窥探私有字段。

四个接缝(前三个全是既有先例,唯一新增是斜杠解析):

1. **REST 路由 + 真实 server 进程**(最高层):kind 建房校验/task 必填 projectPath 400/mode 锁 baton/导入降级 chat+系统消息/导出含 kind 往返/extraArgs 白名单各入口拒绝/skills 扫描端点//model 成员变更路由。先例:import-export-routes.test.ts(真实 HTTP + fetch)。
2. **编排器 fake adapter**(行为层):超时路径(挂起不 resolve 的 fake adapter → 断言占位文案、sessionIds 不清、绝不自动重试);任务房多成员 @ 驱动(干完即停,无自动接棒);scout 跳过。先例:orchestrator.test.ts(29 场景,脚本化 fake adapter)。
3. **prompt 组装断言**:任务段族(工作区段/行为契约/无目录树/无接棒教学/无长度约束/权限文案新措辞 zh/en)。先例:prompt-i18n.test.ts。
4. **斜杠命令解析纯函数**(新增,唯一新接缝):`/` 候选解析与内置命令分流,与 mentions 解析同层同范式(纯函数单测)。

权限翻译纯函数:adapter-permissions.test.ts 直接扩(claude 三档 disallow 契约断言)。

UI 层不做组件测试(仓库无先例,不引入新测试栈),经 i18n 词典键完整性测试兜底。

## Out of Scope

- **git/worktree 隔离**——不做,物理隔离靠"一任务一项目目录"的用户约定
- **并发上限**——任务房并行无闸(记入已知边界,待真实痛感)
- **断点续跑/重启恢复**——重启杀任务无提示,用户发"继续"即 resume 续跑(记入已知边界)
- **路径级硬边界**(OS 沙箱/正向路径白名单)——CLI 无此参数,靠 prompt 软约束,记入已知边界
- **任务状态机扩展**——无待验收/完成/排队态(三态封顶)
- **skill 安装/管理 UI、MCP 管理命令**——只做发现与触发
- **codex 适配器 e2e**——维持零实测现状
- **聊天房行为变更**——chat 房一切照旧(含 scout/接棒/订阅)
